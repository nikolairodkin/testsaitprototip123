# Лендинг-прототип: финансовый учёт и рост прибыли

Статический одностраничный сайт-прототип для консалтингового проекта. Без фреймворков и сборки.

## Как открыть

Достаточно двойного клика по `index.html` — сайт откроется в браузере.

Если хочется отдать прототип по локальной сети или проверить на телефоне, поднимите простой сервер:

```bash
python3 -m http.server 8000
# затем откройте http://localhost:8000
```

## Файлы

| Файл | Назначение |
|---|---|
| `index.html` | Разметка всех секций, обе лид-формы (в модалке и в финальном блоке) |
| `styles.css` | Стили. Цвета, отступы и скругления — в CSS-переменных в начале файла (`:root`) |
| `script.js` | **Объект `CONFIG` со всеми заглушками** + логика: меню, модалка, валидация форм, анимации появления |

## Где менять контент

Почти все заменяемые данные лежат в объекте `CONFIG` в начале `script.js`.
Правите только его — HTML трогать не нужно.

## Список заглушек (заменить перед публикацией)

Всё ниже — в `CONFIG` (`script.js`), если не указано иное.

1. **Название проекта** — `CONFIG.brand.name` (шапка, футер, копирайт, `<title>` вкладки).
2. **Реквизиты** — `CONFIG.brand.requisites` (футер).
3. **Контакты** — `CONFIG.contacts`: телефон (шапка + футер), почта, WhatsApp, Telegram, MAX.
   У каждого контакта два поля: видимый текст и ссылка (`*Href`).
4. **Цифры Hero** — `CONFIG.hero.stats`: N реализованных проектов · X отраслей · XX% средний рост чистой прибыли.
   Подпись-предупреждение под цифрами — в `index.html`, класс `.hero__note` (удалить после замены цифр).
5. **4-й этап работы** — `CONFIG.stage4`: название и описание.
   Кандидаты: сопровождение и контроль результата / масштабирование / регулярная аналитика.
   Карточка визуально помечена пунктиром и плашкой «ЗАГЛУШКА».
6. **Кейсы — раздел временно выключен** (`CONFIG.showCases = false`): реальных кейсов
   по текущему методу пока нет, а выдуманные не публикуем.
   Чтобы вернуть: заменить примеры в `CONFIG.cases` (отрасль, проблема, результат) на реальные
   и поставить `showCases: true`. Пункт «Кейсы» в меню и футере вернётся сам,
   чередование белого и серого фона секций пересчитается автоматически.
7. **Команда — заполнена.** Данные в `CONFIG.team`: имя, должность, путь к фото,
   списки «Регалии» и «Роль» (всплывают при наведении на фото, на телефоне — по нажатию).
   Фото лежат в `img/team/`, формат 3:4, 600×800 px, WebP. Чтобы заменить фото —
   положите новый файл того же формата и поправьте путь `photo`.
8. **Отзывы («Что говорят клиенты») — раздел временно выключен** (`CONFIG.showTestimonials = false`):
   реальных отзывов пока нет, а выдуманные не публикуем.
   Чтобы вернуть: заменить примеры в `CONFIG.testimonials` (имя, компания, дата, текст) на реальные
   и поставить `showTestimonials: true`. Чередование фона секций пересчитается автоматически.
9. **Ссылки на документы** — политика конфиденциальности и пользовательское соглашение,
   в `index.html` (атрибут `data-draft`, клик по ним сейчас ничего не делает).
10. **Дисклеймеры прототипа** — подписи «* … ЗАГЛУШКИ» под блоками кейсов, команды и отзывов
    и строка «Прототип. Часть данных — заглушки» в футере: удалить перед публикацией.

## Формы

Бэкенда нет. При отправке: `preventDefault()`, данные выводятся в консоль браузера,
показывается сообщение «Спасибо! Форма отправлена».
Валидация клиентская: имя (обязательное, от 2 символов), телефон (обязательный, от 10 цифр),
чекбокс согласия на обработку персональных данных.

Чтобы подключить реальную отправку — в `script.js`, функция `initForms()`,
после `console.log(...)` добавьте `fetch()` на ваш обработчик.

## Публикация в интернете (GitHub Pages)

В репозитории уже лежит workflow `.github/workflows/deploy-pages.yml`:
он собирает и публикует сайт при каждом пуше в основную ветку,
а также по кнопке **Run workflow** во вкладке Actions.

Бесплатный GitHub Pages работает только с **публичными** репозиториями, поэтому нужно один раз:

1. **Settings → General → Danger Zone → Change repository visibility → Public**
   (подтвердить, введя имя репозитория).
2. **Settings → Pages → Build and deployment → Source: GitHub Actions**
   (если workflow уже прошёл успешно, этот пункт включится сам).
3. **Actions → Deploy to GitHub Pages → Run workflow** — либо просто сделать любой пуш.

Через 1–2 минуты сайт будет доступен по адресу:

```
https://nikolairodkin.github.io/testsaitprototip123/
```

Дальше при каждом пуше сайт обновляется автоматически.

### Поисковики и превью в мессенджерах

- **Индексация запрещена**: в `index.html` стоит `<meta name="robots" content="noindex, nofollow">`.
  Google и Яндекс не показывают сайт в поиске — его открывают только те, у кого есть ссылка.
  Чтобы разрешить индексацию — удалить эту строку.
- **Превью ссылки** (Telegram, WhatsApp, VK) задаётся метатегами `og:*` в `index.html`
  и картинкой `og-image.jpg` (1200×630). Если меняете заголовок или картинку,
  мессенджеры могут ещё какое-то время показывать старое превью из кэша.
  В Telegram его можно обновить через бота @WebpageBot: отправить ему ссылку.

Шаг «Check the site opens for anyone with the link» в деплое после каждой публикации
открывает сайт без авторизации и проверяет страницу, файлы, запрет индексации и картинку превью.

### Если репозиторий нужно оставить приватным

Бесплатные альтернативы, работающие с приватным кодом:

- **Netlify Drop** — https://app.netlify.com/drop, перетащить папку с `index.html`,
  `styles.css`, `script.js`. Ссылка выдаётся сразу; чтобы сайт остался навсегда
  и получил своё имя — бесплатный аккаунт Netlify.
- **Cloudflare Pages** или **Vercel** — подключить GitHub-репозиторий,
  сборка не нужна (статика): build command оставить пустым,
  output directory — корень репозитория.
